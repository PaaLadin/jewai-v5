## Инструкция: как переносим код из старого проекта

**Главное правило:** код старого проекта (C:/DeepSeek/) не копируется. Никогда. Ни строчки.

**Протокол на каждый модуль:**

1. **Прочитать старый файл целиком.** Не по частям, не «по диагонали».
2. **Выписать контракт.** Что модуль делает полезного. 2–5 строк: вход, выход, обязанности. Например: «cdp: подключиться к Chrome по порту, выполнить JS, вернуть значение, закрыть. Вход — порт и выражение. Выход — результат или ошибка.»
3. **Выписать костыли и почему появились.** Каждая странная ветка, каждый `if legacy`, каждый хардкод — с пометкой «зачем». Пример: «fallback на Playwright — потому что CDP иногда не отвечает на SPA»; «hold/force — потому что автомат перерождения срабатывал ложно».
4. **Решить по каждому костылю:** нужен в новой архитектуре или нет. Если проблема (SPA виснет) в v5 решается иначе (например, всегда bringToFront перед eval) — костыль не нужен, выкинуть с объяснением в JOURNAL.
5. **Написать новый модуль с нуля.** По контракту, не по старому коду. Если старый делал 5 вещей, а контракту нужны 3 — писать 3.
6. **Тест.** Минимальный: импорт, основная функция на реальном входе, обработка ошибки.
7. **Запись в JOURNAL:** «переписан X. Контракт: …. Выкинуто: … (потому что …). Оставлено: … (потому что …).»

**Проверка перед коммитом:**
- В новом файле нет ничего, чего нет в контракте.
- В новом файле нет `import` старого модуля.
- Нет упоминания путей `C:\DeepSeek` (кроме случаев, когда модуль явно читает старые данные для миграции).
- Нет хардкода портов (только из config.json).
- Нет закомментированного кода «на всякий случай».

**Что НЕ переносим вообще:**
- Лада (local_ai, Qwen 3B) — галлюцинирует. В v5 — сетевая LLM по ip:port.
- Playwright — виснет на SPA.
- Attach файла в DeepSeek (`input[type=file]`) — не работает.
- Watermark/Ledger extension — в v5 нет extension.
- Хардкод `C:\DeepSeek` — всё через config.root().
- Мусор: hexxagon, kdp, itch, fix/patch/check, _d_*, _c_*, .bak.
