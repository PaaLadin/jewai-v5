# script_creation — создание нового скрипта

## WHEN

Когда нужен новый скрипт в песочнице: тест, утилита, обёртка, эксперимент.
Любая задача, которую можно автоматизировать кодом.

## WHO

Помощник (agent 8767) — пишет и прогоняет. Ведущий — ставит задачу
и принимает результат. Оператор — только если нужен внешний ввод.

## STEPS

1. Описать задачу одной строкой: что на входе, что на выходе, критерий успеха.
2. Проверить существующие файлы: list sandbox/ — возможно, скрипт уже есть.
   Прочитать похожие через read, взять стиль.
3. Написать файл в sandbox/ (op=write). Первая строка — тег
   `# tag: ...` для фильтра раннера, если это тест.
4. Прогнать: python sandbox/runner_v3.py --filter <имя>.
5. Если FAIL — прочитать stderr/stdout, локализовать ошибку, править,
   прогнать снова. Цикл до зелёного.
6. Если PASS — зафиксировать результат (файл + вывод раннера).
7. Закоммитить в git, если задача того требует и push разрешён
   (см. github_release.md). Иначе — оставить локально.
8. Отчитаться в outbox.json: id, status, result, artifacts.

## STOP

- Скрипт требует прав вне sandbox/ (system, реестр, удаление вне C:\DeepSeek\)
  — стоп, спросить ведущего.
- Скрипт лезет в интернет без явного разрешения — стоп.
- Три подряд неудачных правки без прогресса — стоп, доложить ведущему.
- Появился риск утечки секретов в вывод — стоп, зачистить.

## Правила

- Писать только в sandbox/ (или куда явно разрешил ведущий).
- Блоки-команды оборачивать в code fence.
- Не писать буквальные маркеры в теле файла (собирать динамически).
- Блок >5 КБ разбивать на части.
