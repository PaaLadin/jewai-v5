# Ограничения моста (bridge limits)

**Сборник граблей, набитых за месяцы.** Прочитать до первой команды.

## 1. `op=write` - перезаписывает ЦЕЛИКОМ

`op=write` **не append**. Если файл был 10 КБ, а записал 2 КБ - останется 2 КБ.

**Правило:** перед правкой `read` файл -> сохрани в контекст -> запиши заново с изменениями.

**Для дневников/TODO:** append через python-скрипт, а не `op=write`.

## 2. `op=write` теряет тело при размере

Разные источники дают разные цифры (зависит от парсера):

- **> 200 байт** - иногда теряет (старые логи, `sha256 = e3b0c442` - пусто).
- **> 1.5 КБ** - надёжнее считать, что теряет.
- **> 2 КБ** - почти гарантированно.

**Обход:**

- Дробить на фрагменты 1-1.5 КБ.
- Через PowerShell `Set-Content` (массив строк).
- Через `[System.IO.File]::WriteAllLines` (UTF8Encoding).
- Через python-скрипт: `pathlib.Path(p).write_text(...)`.

**Проверка после write:** `read` файл обратно, сравнить байты.

## 3. Литеральные ### и ``` в теле write рвут блок

**Симптом:** блок обрезан на первой строке с маркером.

**Причина:** мост ищет маркеры ###BEGIN### / ###END### в тексте.
Если они в теле write - парсит как новую команду.

**Правила:**

- **Никогда не писать** литеральные ###BEGIN### в теле write.
- **Никогда не писать** литеральные ``` (три бэктика) в теле write.
- Для кода в markdown - собирать через `chr(35)*3` / `chr(96)*3`.
- Или через `@BT@` / `@H@` + replace.

**Пример (python):**

```
H = chr(35) * 3
F = chr(96) * 3
text = "блок: " + H + "BEGIN" + H + " ... " + H + "END" + H
pathlib.Path(p).write_text(text)
```

## 4. Кириллица в stdout моста бьётся

**Симптом:** в `[AGENT REPORT]` вместо "Привет" - крякозябры.

**Причина:** stdout моста идёт через cp1251.

**Обход:** python-скрипт пишет результат **в файл** (utf-8), я читаю файл через `op: read`.

## 5. Многострочный python -c не работает

**Симптом:** пустой stdout / SyntaxError.

**Причина:** мост парсит cmd как одну строку.

**Правило:** любой многострочный python -> файлом, потом `op: run` с `cmd: python <файл>.py`.

## 6. findstr с несколькими /c: - падает

Обход: по одному /c:, или python-однострочник, или Tools/find.py.

## 7. cmd ест > и | как редирект

`cmd /c "... > file"` - редирект в file.

**Обход:** `chr(62)` вместо `>`, `chr(124)` вместо `|`, или python-скрипт.

## 8. op=run через path: - пустышка

`op: run` с `path:` вместо `cmd:` - ничего не выполнит.

**Правило:** для `op=run` только `cmd:` + `cwd:` + `timeout:`.

## 9. Поиск по дереву - только Tools/find.py

**Симптом:** "rglob" или Get-ChildItem -Recurse висит 60+ секунд.

**Причина:** в runtime/chrome/<L>/ десятки тысяч файлов Chrome-профиля.

**Правило:** только Tools/find.py.

```
python Tools/find.py "*.py"
python Tools/find.py "pattern" --text
python Tools/find.py "*.md" --dir rag
```

## 10. Кик и broadcast - короткие

**Кик (bridge_kick2.py):** длинные рвутся, доходит первая строка. Ядро в первые 100 символов.

**Broadcast (say.py):** то же.

**Правило:** короткое сообщение, суть в начале, детали - в файле (дать ссылку).

## 11. op=write с одинаковым содержимым - unchanged

**Симптом:** write прошёл, но файл не изменился.

**Причина:** мост делает sha256, если совпало - не пишет (unchanged: true).

## 12. Многострочный cmd с powershell

op: run с cmd: powershell -c "..." - часто падает на кавычках.

**Правило:** для powershell - файлом .ps1, потом cmd: powershell -File <файл>.

## 13. Таймаут моста

op: run с длинным timeout (60+) - мост сам режет по 60.

**Для долгих операций:** subprocess.Popen(..., DETACHED_PROCESS) внутри python-скрипта, отчёт сразу, результат в файл.

## 14. op=delete - не использовать без явного ОК

Удаление файлов/папок - необратимо. Не делать без явного разрешения оператора.

st_size=0 у директории на Windows - **всегда 0**, это не признак пустоты.

## 15. Что делать при сомнении

- Не писать многострочный -c - файлом.
- Не пихать литеральные маркеры в write - через chr()/переменные.
- Кириллицу - в файл.
- find - через Tools/find.py.
- После write - read обратно.
