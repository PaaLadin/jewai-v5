# Коллекция стопоров DeepSeek (и SPA)

Сборник известных зависаний браузерных чатов и методы их программного обхода. Используется для превентивных фиксов (checkStuck) в content*.js.

---

## Тип 1: Server is temporarily unavailable (сетевой стопор)
**Симптом:** DeepSeek прерывает генерацию сообщением "Server is temporarily unavailable." (или Network Error). Внизу появляется кнопка **Continue** (или Try again).
**Причина:** Серверная ошибка, обрыв WebSocket, таймаут.
**Фикс:** Найти кнопку "Continue" и кликнуть.
**Скриншот-пруф:** 13A (26.10).

---

## Тип 2: Утечка системного промпта <ds_safety>
**Симптом:** Модель выдает сырой текст правил безопасности (например, <ds_safety>Safe</ds_safety> или длинные логи классификации) и перестает отвечать по существу.
**Причина:** Сбой модели, галлюцинация, переполнение контекста.
**Фикс:** Найти кнопку **Regenerate** (или Перегенерировать) и кликнуть. **Внимание:** жать только если в тексте есть теги безопасности, иначе можно зациклиться.
**Скриншот-пруф:** D (25.10).

---

## Тип 3: Вечное "Thinking"
**Симптом:** Модель показывает индикатор размышления (Thinking) и не выдает текст.
**Причина:** Зависание на сервере.
**Фикс:** Найти кнопку **Stop** (Остановить), кликнуть. Дождаться остановки. Отправить "продолжай".

---

## Тип 4: Пустой ответ / Network Error
**Симптом:** Модель ничего не отвечает, сообщение не отправляется.
**Фикс:** Кнопка Retry / Regenerate / Повторить.

---

## Архитектура превентивного фикса (checkStuck)
- Внедрено в content.js, content_qwen.js, content_alice.js.
- Защита: не кликает, если есть кнопка Stop (идет генерация).
- Защита: не кликает, если пользователь печатает (userHasTyped).
- Дедупликация: не кликает чаще, чем раз в 15 секунд (RETRY_COOLDOWN_MS).
- Логирование: пишет в мост при нажатии.


## Тип 2 (расширенный): Утечка технических тегов и иероглифов
**Симптом:** Модель выдает сырой текст системных правил в общий чат. Теги могут быть разными: <ds_safety>, <system_warning>, <error>, вплоть до иероглифов (китайский лог).
**Причина:** Сбой генерации, утечка внутреннего состояния. Мост не видит корректного конца ответа и зависает.
**Фикс:** Найти кнопку **Regenerate** (или Повторить/Retry) и кликнуть.
**Внимание:** патч должен игнорировать теги внутри markdown-блоков кода (иначе будет ложно срабатывать на блоках с HTML/XML).
**Скриншот-пруф:** 13A (26.10).

## Тип 5: Feedback / Preference screen (Qwen, E/F)

**Симптом:** Qwen после генерации показывает экран оценки:
«Этот отзыв поможет нам оценить и улучшить работу Qwen. Какой ответ
вы предпочитаете? Выберите один, чтобы продолжить.» Две карточки
с кнопками «Предпочитаю этот ответ».

**Что видит панель:** статус «Не удалось отправить отчёт», агент
сгенерировал блок (например QQAA0111), но мост не может его
отправить — textarea и кнопка Send скрыты за экраном фидбэка.

**Почему агент висит:** команда в DOM есть, отчёт не уходит,
[AGENT REPORT] не приходит. Агент ждёт ответа, которого не будет.
ALIVE не помогает — канал моста занят непрочитанным блоком.

**Причина:** Qwen периодически включает A/B-оценку ответов. Это
штатное поведение их UI, не сбой сети и не лимит.

**Фикс (для checkStuck в content_qwen.js):**
1. Детект: искать текст «Какой ответ вы предпочитаете» или
   «Предпочитаю этот ответ» на странице.
2. Действие: кликнуть первую кнопку «Предпочитаю этот ответ»
   (или «Пропустить», если есть).
3. После клика экран закрывается, textarea возвращается,
   отчёт уходит.
4. Дедуп: RETRY_COOLDOWN_MS (15 с).

**Псевдокод:**
```javascript
const pageText = document.body ? document.body.innerText : "";
if (pageText.includes("Какой ответ вы предпочитаете") ||
    pageText.includes("Предпочитаю этот ответ")) {
  const prefBtn = Array.from(document.querySelectorAll("button"))
    .find(b => (b.textContent || "").includes("Предпочитаю этот ответ"));
  if (prefBtn) { prefBtn.click(); return; }
}
```

**Скриншот-пруф:** E (8771, Qwen), 26.10 18:41, lastId QQAA0110,
pending QQAA0111. Панель: content v1.1.3, статус «Не удалось
отправить отчёт».

**Важно:** это отдельный тип, не путать с Типом 1 (Server unavailable)
и Типом 2 (утечка тегов). Лечится кликом, а не Regenerate.

**Дополнение:** похожий механизм возможен и у F (Алиса) — та же
логика A/B-оценки. Проверить при первом случае.
