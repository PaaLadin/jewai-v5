# backup_rule.md — обязательный бэкап перед правкой

## WHEN

Перед ЛЮБОЙ правкой существующего файла — read, write, patch, run
с модификацией. Без исключений.

## WHO

Все каналы: A, B, C, D. Правило распространяется на агентов и на
оператора через агентов.

## STEPS

1. **Прочитать** текущий файл (op=read) — знать, что правишь.
2. **Сделать бэкап**: скопировать рядом с суффиксом.
   Формат суффикса: `.bak_<YYYYMMDD_HHMM>` или `.bak_<причина>`.
   Пример: `SESSION_STATE.md.bak_v32`, `2026-10.md.bak_before_4a`.
   Команда:
       python -c "import shutil; shutil.copy2(r'C:\DeepSeek\путь', r'C:\DeepSeek\путь.bak_<суффикс>')"
3. **Править** файл (op=write или patch).
4. **Проверить результат**: op=read, убедиться, что содержимое
   корректно (голова, хвост, ключевые секции на месте).
5. **Записать факт** в свой дневник (logs/<роль>/YYYY-MM.md):
   что правил, где бэкап, что проверял.

## КРИТИЧНО: файлы без бэкапа

Нельзя править без бэкапа:
- SESSION_STATE.md
- logs/A|B|C|D/YYYY-MM.md (дневники)
- assistant/outbox.json, inbox.json
- council/threads/*.md (задачи, если уже есть ответ)
- algorithms/*.md (процедуры)
- extension_v2/*.js, agent.py, launchers/*
- MILESTONE.md, TODO_*.md

## Проверка после правки

- Файл открывается (op=read → OK).
- Размер не 0 байт.
- Ключевые маркеры на месте (для дневника — заголовок и последний
  блок; для JSON — валидность).
- Если правил write — нет обнуления (известная грабля: op=write
  без CONTENT обнуляет файл).

## Пример инцидента (2026-10-05)

3A ночью правил `logs/A/2026-10.md`, write потерялся под нагрузкой,
файл обнулился до 869 байт (было 63423). Восстановление: 4A взял
`logs/B/conversations/3A_share.md` (там сохранён AGENT REPORT с
полным телом), `.fix`, `.draft_task`. Итог: 47857 байт — потеряно
~15 КБ истории.

**Урок:** если бы 3A делал бэкап перед правкой дневника — откат был
бы мгновенным, история сохранилась бы полностью.
