# Kick protocol — как агенты общаются (v5)

**Главный источник путаницы у моделей.** Прочитать до первого сообщения в чат.

## 0. Что есть в v5 (только это)

| Инструмент | Что делает | Где |
|---|---|---|
| `Tools/kick.py` | Отправить сообщение в чужой канал через CDP | `Tools/kick.py` |
| `Mainframe/council.py` | Общий чат (chat.jsonl) + персональные (chat_<CH>.jsonl) | `Mainframe/council.py` |
| `Mainframe/server.py` | HTTP-роуты: `/api/send`, `/api/chat/<CH>` | `Mainframe/server.py` |

## 1. Три разных способа «написать» — не путать

| Что | Транспорт | Кто видит |
|---|---|---|
| **Кик коллеге** | `python Tools/kick.py --to B --from A --text "..."` | Только B |
| **Общий чат (broadcast)** | `POST /api/send {"from":"A","to":"ALL","text":"..."}` | Все + оператор |
| **Персональный чат (оператору)** | `POST /api/chat/<CH> {"from":"A","text":"..."}` | Только оператор |

**Три разных транспорта. Не взаимозаменяемы.**

## 2. Правила выбора

### 2.1. Агент → агент (p2p)

**Маркер:** `[X>Y]`. **Транспорт:** `Tools/kick.py`.

```
python Tools/kick.py --to B --from A --text "[A>B] вопрос по аудиту"
```

`--to` = буква получателя (A-F). Скрипт сам найдёт CDP-порт из config.
`--from` = буква отправителя (для маркера).

**Что видит B:** сообщение в своём чате с маркером `[A>B]`. Оператор НЕ видит.

### 2.2. Агент → все (broadcast)

**Маркер:** `[X>ALL]`. **Транспорт:** `POST /api/send`.

```
POST /api/send {"from":"A","to":"ALL","text":"[A>ALL] 21/21 тестов"}
```

**Что видят все:** сообщение в `logs/council/chat.jsonl`, читают все агенты и оператор.

### 2.3. Агент → оператор (персональный чат)

**Маркер:** `[X>OP]` (в совещании `>ALL`). **Транспорт:** `POST /api/chat/X`.

```
POST /api/chat/A {"from":"A","text":"[A>OP] личный доклад"}
```

**Что видит:** только оператор. ACL: писать может только оператор или сам канал A.

### 2.4. Оператор → агент

Приходит как кик в личный чат агента (`Tools/kick.py`) или как broadcast в общий.

Агент видит сообщение как обычный текст. Реагирует по контексту.

## 3. Инварианты (нарушение = провал задачи)

1. **P2P не публикуется в общий чат.** Маркер `[A>B]` + `/api/send` = ошибка канала.
2. **Broadcast не кикается в один порт.** Маркер `[A>ALL]` + `kick.py` = ошибка.
3. **Персональный чат — не p2p и не broadcast.** Только `POST /api/chat/<CH>`.
4. **В общий чат не пишем персональные id.** id-формат `Z<CH>AA<NNNN>` только в `/api/chat/<CH>`.

## 4. Признак ошибки

- **Ждёшь ответа коллеги — нет** → написал в свой чат (не `Tools/kick.py`).
- **Коллега отвечает «как оператор»** → кик без маркера `[X>Y]`.
- **Оператор говорит «я не видел»** → отправил p2p вместо broadcast.
- **Коллега не понимает контекст** → отправил broadcast вместо p2p.

## 5. Кик короткий

**Длинные кики рвутся, доходит первая строка.** Ядро — в первые 100 символов.

Плохо: привет, у меня тут проблема с аудитом, во-первых 29 разделов, во-вторых 8 зон...

Хорошо: `[A>B] Проблема с replay-guard, см. council/threads/A_to_B.md`

## 6. Кик только при пустой textarea

`Tools/kick.py` проверяет textarea получателя. Непустая → FAIL (не форсит). Текст оператора не трогаем.

## 7. Как агент в чате отправляет кик

Агент в чате **не может** вызывать `Tools/kick.py` напрямую — нет shell.

Пишет блок `op: run` → мост исполняет `Tools/kick.py` → сообщение летит.

```
###BEGIN###
id: CCAA1001
op: run
cmd: python Tools/kick.py --to B --from A --text "[A>B] вопрос"
cwd: <корень>
timeout: 60
###END###
```

**Важно:** `--text` содержит маркер `[A>B]` — он доедет до B, B поймёт «это от A».

## 8. Куда смотреть, если не так

- `Tools/kick.py` возвращает exit code: 0 = OK, 3 = нет CDP, 4 = textarea busy, 5 = buffer fail.
- `stderr` в `[AGENT REPORT]` — что именно упало.

## 9. Канон (шпаргалка)

| Надо | Маркер | Транспорт |
|---|---|---|
| Сказать коллеге | `[X>Y]` | `Tools/kick.py --to Y --from X` |
| Сказать всем | `[X>ALL]` | `POST /api/send` |
| Сказать оператору | `[X>OP]` | `POST /api/chat/X` |
| Ответ на `[A>B]` | `[B>A]` | `Tools/kick.py --to A --from B` |

**Без маркера = оператор.** Увидел без `[...]` — это человек, не коллега.
