# Стопоры SPA (stuck states)

**Коллекция типовых зависаний DeepSeek/Qwen/Alice + методы обхода.**

## 1. Тип 1: Server is temporarily unavailable

**Симптом:** SPA прерывает генерацию сообщением "Server is temporarily unavailable." (или Network Error), внизу кнопка **Continue** (или Try again).

**Причина:** серверная ошибка, обрыв WebSocket, таймаут.

**Фикс:** клик по Continue.

**Подвид:** "This model is currently unavailable. Please wait and try again later." + кнопка **Retry**.

**Фикс:** клик по Retry (тот же алгоритм, другие слова).

## 2. Тип 2: Утечка системного промпта

**Симптом:** SPA выдаёт сырой текст правил (`<ds_safety>`, `<system_warning>`, `<error>`) или иероглифы (китайский лог).

**Причина:** сбой генерации, утечка внутреннего состояния.

**Фикс:** клик по **Regenerate** (Перегенерировать).

**Важно:** жать **только если в тексте есть теги/иероглифы вне markdown-блоков** (иначе можно ложно сработать на HTML/XML).

## 3. Тип 3: Вечное Thinking

**Симптом:** SPA показывает индикатор размышления и не выдаёт текст.

**Причина:** зависание на сервере.

**Фикс:** клик по **Stop** (Остановить), дождаться остановки, отправить "продолжай".

## 4. Тип 4: Пустой ответ / Network Error

**Симптом:** SPA ничего не отвечает, сообщение не отправляется.

**Фикс:** Retry / Regenerate / Повторить.

## 5. Тип 5: Qwen feedback screen (E/F)

**Симптом:** Qwen после генерации показывает экран "Этот отзыв поможет нам оценить и улучшить работу Qwen. Какой ответ вы предпочитаете?" Две карточки с кнопками "Предпочитаю этот ответ".

**Что видит панель:** "Не удалось отправить отчёт", агент сгенерировал блок, но мост не может отправить (textarea и кнопка Send скрыты за экраном).

**Причина:** Qwen периодически включает A/B-оценку ответов.

**Фикс:** детект текста "Какой ответ вы предпочитаете" / "Предпочитаю этот ответ" -> клик первой кнопки. После клика экран закрывается, textarea возвращается.

**Подвид:** у Alice может быть та же логика A/B-оценки.

## 6. Архитектура превентивного фикса (checkStuck)

Внедрено в `Templates/extension/content_*.js` (v5, но модель через CDP - см. `Bridge/exec.py`).

**Логика:**

1. Раз в 2 сек сканировать DOM.
2. Если Type 1 (Continue/Retry) - клик.
3. Если Type 2 (теги/иероглифы вне `pre`/`code`) - клик Regenerate.
4. Если Type 5 (feedback screen) - клик "Предпочитаю этот ответ".

**Защита:**

- **Не кликать, если есть кнопка Stop** (идёт генерация).
- **Не кликать, если оператор печатает** (`userHasTyped`).
- **Дедуп 15 сек** (`RETRY_COOLDOWN_MS`) - не спамить.
- **Игнор HTML-тегов внутри `pre`/`code`** - не ложно срабатывать на код.

## 7. Что делать агенту при стопоре

**Если вижу Type 1/2/3/4 в чате:**

- Ждать (мост сам обработает через checkStuck).
- Не пытаться "исправить" своими командами - я не вижу DOM.

**Если вижу панель "Не удалось отправить отчёт":**

- Это Type 5 (feedback screen).
- Сказать оператору: "feedback screen Qwen, нужен клик".
- Или `Tools/see_chat.py` для диагностики.

## 9. Что НЕ путать

- **Type 1** (Server unavailable) -> клик **Continue**.
- **Type 2** (теги/иероглифы) -> клик **Regenerate**.
- **Type 3** (Thinking) -> клик **Stop** + "продолжай".
- **Type 5** (feedback Qwen) -> клик **"Предпочитаю этот ответ"**.

Разные действия - не перепутать.
